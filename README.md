# Aqara Logger

I came across the Aqara Zigbee and Matter products. They have an enormous portfolio of sensors, camera's, etc. that look really nice and are low cost. They are nicely engineered and work.

To measure the in-house climate I use the T1T1 Humidity and Temperature Sensors. These are little sensors that can be attached to anything. They have a CR2032 battery, a blue led, Zigbee and a temperature and relative humidity sensor. The app/sensor also feature a barometer, but that is a location derived value w/o a sensor.

The app on my iPhone is OK. Installing is fine. However, if you want to correlate data from sensors you are limited to three in one overview :-(.

It is good to now that pressing the button shortly will initiate a reading, pressing for 5 seconds will initiate a install/binding process.

Like wise the HUB (M-100) can be instructed to go to factory settings by pressing the button 10 times after each other (flashing yellow). Reinstalling/binding is by pressing 4 times. (flashing blue)

One of the nice features is that the hub allows more than one client (five in total). So I use Aqara's own application on the iPhone, have Apple Home, use Home Assistent and add this one the Aqara Logger.

## Aqara T1 Climate Logger Project

Logs Aqara T1 temperature/humidity sensors from an **Aqara Hub M100** to CSV, locally,
over **Matter**. Shows them on a screen, exports time-aligned tables for charts, and calibrates the sensors against each other.

## Aqara Logger on a Raspberry Pi
Any (Linux) system wil do, but as I have a RASPI4 available for experiments and a lot of users have experience with the Raspberry Pi it is a good choice. It is "portable" enough to move it to any Linux platform as long as the **matter-server** is available.

### Logger
The dashboard reads from a file that contains the latest reading. This json file is generated by the logger. The logger timestamps the data that comes from the sensors via the hub. Data is coming in as an "interval" and "update". The "update" values are new readings.

watch -n 30 '(head -1 ; tail -n 20) < /opt/aqara/app/sensor_log.csv | column -t -s,'

### Note
Sometimes the sensors are moved from location or a battery is replaced. Using `note` it is possible to make a timestamped note so it can be correlated with the log file.

### Export
Having a large log file is one thing, doing something sensible with it is another. The export file is able to rearrange the data so all sensors can be correlated to each other together with the time stamp. Also a period can be compared to another (like week by week).

Not only data exports, but sensor correction as a convenience. If the calibration method is used the data over a long interval is taken and correction values of the sensors are determined making them all "equal". This is kept in a seperate file. The log file are the raw data of the sensors. The corrections can be applied when exporting. Also the dashbord can be instructed to use the corrections when displaying the values. To create a correction file, some sort of calibration is necessary. One way is to put the sensors together in a room which has a constant temperature/relative humidy over a long period of time (like at night). Otherwise they can be put into an oven (closed environment) with say 30-40 degrees temperature. The readings of all sensors will then be the "same". However, it is not certain it will be the same as the "real" temperature and humidity. For the temperature it would be best to put all sensors in a water resistent bag and put them in ice water. The temperature is known and pretty stable. It cna be used as an absolute reference.
